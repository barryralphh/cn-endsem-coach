# TCP Flow Control and Throughput

## 10 Golden Points
1. Flow control stops a fast sender from overflowing a slow receiver
2. TCP uses a sliding window, the receiver advertises its window size in every ACK
3. Receiver window rwnd = buffer size minus bytes received but not yet read by the application
4. Sender can send from the ack number up to ack number plus window minus 1
5. Window field is 16 bits, so the maximum window is 65535 bytes without scaling
6. Window scale option shifts the window left by up to 14 bits, allowing about 1 GB
7. Sender window = minimum of rwnd and cwnd
8. Bandwidth delay product BDP = bandwidth x round trip time
9. Utilization = window size divided by BDP, throughput = window size divided by RTT
10. A zero window stops the sender, then the persistence timer sends probes. Silly window syndrome is fixed by Nagle and Clark

## Worked calculations

### Scene 1: Flow control = tanki overflow na ho. Window = khaali jagah
    ## rwnd numerical
    buffer = 4000 B
    received = 1500 B
    read = 500 B
    used = 1500 - 500 = 1000
    rwnd = 4000 - 1000
    ! rwnd = 3000 bytes

### Scene 2: Send range = ack number se (ack + window - 1) tak
    ## ACK=5001, win=2000
    first byte = 5001
    last byte = 5001 + 2000 - 1
    ! can send 5001 .. 7000
    ## ACK=6001, win=1000
    last = 6001 + 1000 - 1 = 7000
    ! window shrank, same right edge
    ## win = 0
    sender stops, persistence timer probes

### Scene 3: BDP = BW x RTT. Utilization = Window / BDP
    ## Q: 10 Mbps, RTT 40 ms, W = 16000 B
    BDP = 10e6 x 0.04 = 400,000 bits
    BDP = 400,000 / 8 = 50,000 bytes
    util = 16,000 / 50,000
    ! Utilization = 32 %
    throughput = W / RTT
    = 16000 x 8 / 0.04
    ! = 3.2 Mbps

### Scene 4: Max throughput = 65535 x 8 / RTT (bina window scaling)
    ## Q: RTT = 100 ms, no scaling
    W = 65,535 bytes
    bits = 65,535 x 8 = 524,280
    thr = 524,280 / 0.1
    ! = 5,242,800 bps = 5.24 Mbps
    ## With scaling 2^14
    W = 65,535 x 16,384
    ! ~ 1.07 GB

### Scene 5: Silly window: Nagle (sender) + Clark (receiver)
    ## Overhead example
    1 byte data + 40 B headers
    efficiency = 1 / 41
    ! = 2.4 % only
    ## Full segment
    1460 B data + 40 B headers
    efficiency = 1460 / 1500
    ! = 97.3 %
