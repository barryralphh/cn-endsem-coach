# SHA, Digital Signature and IPsec

## 10 Golden Points
1. A hash function converts any size message into a fixed size digest
2. Properties: one way, weak and strong collision resistance, avalanche effect
3. SHA-1 digest is 160 bits, block size 512 bits, 80 steps. MD5 digest is 128 bits
4. SHA-256 digest is 256 bits, block 512 bits, 64 steps. SHA-512 digest is 512 bits, block 1024 bits, 80 steps
5. Hex digits in digest = digest bits divided by 4, SHA-1 gives 40 hex digits, SHA-256 gives 64
6. Padding makes message length equal to 448 mod 512 and then 64 bits of length are added
7. At least one bit of padding is always added, a single 1 followed by zeros
8. Digital signature: hash the message and encrypt the hash with the sender private key
9. Signature gives integrity, authentication and non repudiation, but not confidentiality
10. IPsec has AH for authentication, protocol 51, and ESP for encryption, protocol 50, in transport or tunnel mode

## Worked calculations

### Scene 1: Hash = fingerprint: fixed size, one-way, avalanche
    ## Digest sizes
    MD5     128 bits
    SHA-1   160 bits
    SHA-256 256 bits
    SHA-512 512 bits
    ## In hex (bits / 4)
    SHA-1: 160 / 4 = 40 digits
    SHA-256: 256 / 4 = 64 digits
    ! 4 bits = 1 hex digit

### Scene 2: SHA table: digest / block / steps
    ## SHA-1 flow
    1. Pad message
    2. Append 64-bit length
    3. Split in 512-bit blocks
    4. Init 5 words (A,B,C,D,E)
    5. 80 steps per block
    ! Output = 160-bit digest
    ~ each word = 32 bits, 5 x 32 = 160

### Scene 3: Pad to 448 mod 512, phir +64 bits length
    ## Q1: 400 bits
    need 448 mod 512
    padding = 448 - 400 = 48 bits
    total = 400 + 48 + 64 = 512
    ! 1 block
    ## Q2: 1000 bits
    1000 mod 512 = 488
    padding = 472 (to reach 960)
    total = 1000 + 472 + 64 = 1536
    ! 1536 / 512 = 3 blocks

### Scene 4: Signature = hash ko private key se encrypt. Verify = public key se
    ## Check
    equal -> valid
    different -> tampered
    ## Gives
    integrity
    authentication
    non-repudiation
    ! No confidentiality
    ~ encrypt message separately for secrecy

### Scene 5: IPsec: AH (51) auth | ESP (50) encrypt | Transport vs Tunnel
    ## Overhead example
    original packet = 1000 B
    tunnel adds new IP hdr = 20 B
    plus ESP hdr/trailer ~ 30 B
    ! new size ~ 1050 B
    ~ MTU matters in tunnels
